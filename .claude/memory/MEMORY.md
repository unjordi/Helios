- [Moonlight · doc](moonlight-doc-sintesis.md) — **el CONTRATO del protocolo** que los 3 forks hablan idéntico: puertos fijos (UDP 47998=video / 47999=control / 48000=audio), handshake RTSP (OPTIONS/DESCRIBE/SETUP×3/ANNOUNCE/PLAY — `STAGE_MAX=12` es el enum de conexión, NO el nº de mensajes RTSP), pairing PIN+cert, control ENet bundleado, **`SS_ENC_CONTROL_V2` AES-GCM IV=seq 12B**, input AES-GCM, video RTP+FEC; 4:4:4/AV1/HEVC-RExt = extensiones Sunshine (`SCM_*`). No tocar ABI de common-c ni ENet bundleado. Helios/Selene montan el MISMO fork de common-c pero en pins DISTINTOS (Helios `c999436` / Selene `ad329b2`, 5 atrás) → **co-bumpear al mismo pin** (bump = cambio de protocolo coordinado).
- [Moonlight · issues/foros](moonlight-issues-forums.md) — **common-c MUY activo → no congelar el submódulo**; **#120 LTR frames** (cambio de protocolo coordinado host+cliente, ya aterrizando); qt #1300 control-stream error (regresión v6.0); racimo HDR-Linux (Vulkan+Wayland+KDE = stack Jordi); moonlight-qt release estancada (v6.1.0 sept-2024).
